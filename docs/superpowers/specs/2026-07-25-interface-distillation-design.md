# 168 Audit Interface Distillation

**Date:** 2026-07-25  
**Status:** Accepted

## Product Principle

The audit should keep attention on one decision: how a person wants to use a fixed 168-hour week, how reality differed, and what changes next. Every permanent control must support that decision, recovery, or trust.

## Global Shell

- Keep the product name, active schedule, theme, data access, help, and account Center.
- Use a compact utility cluster and a single workflow rail.
- Keep the save state visible and specific: local, syncing, synced, pending, or failed.
- Preserve 44 px targets, focus visibility, reduced motion, and keyboard navigation.

## Plan

- Keep Ideal, Actual, and Side by side stages.
- Use one category navigator on narrow screens.
- Give Add subcategory the strongest action weight.
- Present Snapshot and number/slider mode as adjacent named icon controls.
- Group rows by category. On narrow screens, show the category once and render subcategories as compact rows.
- Collapse visual scaffolding around empty notes while preserving existing notes and every underlying field.
- Use one reconciliation strip for the active stage.

## Compare

- Lead with the dominant gap and totals.
- Rank meaningful gaps first.
- Initially hide negligible or zero rows behind Show all.
- Keep direct Edit actions and a single path into reflection.
- Keep distribution graphics under disclosure.

## Reflect

- Use a focused sequence: surprise, important gap, cause, next-week experiment.
- Show progress and preserve prior answers in collapsed summaries.
- Keep autosave and export compatibility.

## History

- Use a compact chronology with date, label, totals, and commitment.
- Keep snapshot creation in Plan.
- Enter a dedicated two-selection mode for comparisons.
- Put deletion in a row menu and name the affected snapshot in confirmation.

## Schedule, Data, and Help

- Call browser profiles “Schedules.”
- Keep switch, create, rename, duplicate, and delete in one schedule surface.
- Group Data into Backup, Share, and Other formats; show the storage scope before an action.
- Offer one adaptive walkthrough plus shortcuts, privacy, and feedback.
- Replace native prompts and confirms with one reusable accessible dialog system.

## Center

- Treat Center as an optional account and collaboration surface.
- Keep local auditing complete while signed out.
- Make cloud weeks private by default.
- Require an explicit week-to-group share before another member can read an audit.
- Separate personal weeks, groups, roster/invitations, and shared-week reading.

## Responsive Contract

- Desktop: dense ledger with aligned numeric columns and at least ten ordinary rows visible at 1440×900.
- Short desktop: current task and at least four rows visible at 1280×600.
- Tablet landscape: ledger; tablet portrait: focused compact category.
- Phone: compact shell, one-line workflow rail, stage/reconciliation, category navigator, one toolbar, and at least two ordinary rows within a 568 px viewport.
- Hard gates: 320×568, 812×375, 200% zoom, both themes, reduced motion, no page-level horizontal scroll.

## Acceptance

- Every existing field, export, import, snapshot, reflection, and recovery path remains usable.
- Icon controls have persistent accessible names and explanatory tooltips.
- No critical or serious automated accessibility findings.
- Privacy and save-state language matches actual storage behavior.
- The full local workflow remains functional without Supabase configuration or network access.
